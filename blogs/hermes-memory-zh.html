长期记忆：事实落盘，会话进 FTS5

基于真实源码拆解 Hermes 的两条记忆线——写盘的事实记忆，与建全文索引、可跨会话检索的会话记忆。

DL
By Daniel Liu · August 23, 2026 · 8 min read

系列最后一篇讲持久化：Hermes 并行跑两条记忆线。事实经 MemoryManager 落到 MEMORY.md 等文件；会话历史在 SessionDB 里建 FTS5 全文索引（含 CJK），支撑 session_search 跨会话检索。下文沿这两条路径展开，说明并发下原子写入与 drift 检测如何避免静默覆盖外部编辑，并介绍可选社区 provider post-cortex——在自托管 daemon 上做类型化记录与语义召回。

事实记忆

事实经 MemoryManager → MemoryProvider——后台线程、串行、去噪。最朴素的实现 MemoryStore（tools/memory_tool.py:159）通过 save_to_disk()（:387）把 MEMORY.md 直接落盘。方法本身很小；安全性在 _write_file：它用原子临时文件 + rename，并发读取者永远不会看到一个写一半的文件：

def save_to_disk(self, target: str):
    """Persist entries to the appropriate file. Called after every mutation."""
    get_memory_dir().mkdir(parents=True, exist_ok=True)
    self._write_file(self._path_for(target), self._entries_for(target))

@staticmethod
def _write_file(path: Path, entries: List[str]):
    """Atomic temp-file + rename: readers see old OR new, never empty."""
    content = ENTRY_DELIMITER.join(entries) if entries else ""
    atomic_write_text(path, content, tmp_prefix=".mem_")

这就是耐久的"我对用户已知什么"的存储。

会话记忆

另一条线是会话级的：hermes_state.py 用 FTS5 建全文索引，含 CJK 分词器 messages_fts_cjk（:2685）。这个索引是 session_search 的底座——能跨历史会话检索，而不只是单次会话内。

并发下的安全写入

朴素的 MemoryStore 曾有一个竞态：两次读文件中间夹一次写，可能静默覆盖外部编辑。修复是只重读一次目标，然后在同一份快照上同时做 drift 检测与解析——这样两次操作之间的外部写入不会被无察觉地覆盖。调用 save_to_disk() 的 add() 路径（:414）才露出真纪律：改动前在锁内重读磁盘、拒绝完全重复、若文件读成空（瞬时抖动，否则会清空所有历史记忆）则拒绝写：

def add(self, target, content):
    with self._file_lock(self._path_for(target)):
        if self._reload_target(target, skip_drift=True) is _READ_FAILED:
            return _read_failed_error(self._path_for(target))

可选 provider：post-cortex

上文均为 Hermes 内置记忆。社区插件 post-cortex（catalog 收录）是另一套 MemoryProvider：Hermes 插件 + 自托管 daemon，把类型化记录写入实体图并用本地语义检索召回。面向需要结构化知识（决策、已修复问题、代码变更、需求）、每轮前召回、以及跨 profile / 客户端共享 workspace 且数据留在本地的场景（RocksDB 或 SurrealDB、本地 embedding）。代码：hermes-plugin-post-cortex 与 post-cortex（Rust daemon）。经 memory.provider: post-cortex 切换，不改写前面章节的网关架构。

每个 profile 通过 HTTP 连一个 daemon（默认 http://127.0.0.1:3737）。插件用 post-cortex.json 里的 glob 映射 workspace，并打开每 profile 一条 session（默认 hermes:{profile}）。daemon 用本地模型做 embedding 与混合检索。

轮次前召回

auto_recall 开启时，每轮开始前对 profile 对应 workspace 做语义检索。弱相关、空实体描述及 skip_patterns 命中的噪声会丢弃。高于 min_score（默认 0.62）的记录最多注入 max_items（默认 5）条，并按 item_chars 截断。daemon 慢或不可达时在 timeout_s 后跳过召回，轮次照常进行。

工具与 skill

  • post_cortex_search — 对记录（及可选 capture 消息）做语义搜索。
  • post_cortex_record — 写入类型化记录进图。
  • post_cortex_context — 指定组件的邻域与反向依赖。
  • skill_view("post-cortex:memory") — 记录格式与检索提示。

daemon 0.5+ 支持 cards（用户卡与项目卡写入 system prompt）、authorship（记录带 hermes:{profile}）、以及可选 capture 把完成的轮次写入消息流（仅主 Agent；cron 与子 Agent 不会自动写入）。

镜像与 workspace

mirror_memory_writes: true 时，主 Agent 通过内置 memory 工具保存的内容会同步为 post-cortex 记录；cron 与子 Agent 不会自动镜像。workspaces 用 profile 名 glob 映射共享 workspace（先匹配者优先），例如 {"ops-*": "Ops", "dev-*": "MyProject", "*": "hermes"}，同一项目上的其他 post-cortex 客户端也可读同一图。

安装与配置

  • Hermes ≥ 0.22.2；daemon ≥ 0.4.0（cards、authorship、capture 需 0.5.0）。
  • hermes plugins install post-cortex，再 hermes memory setup（或在 profile config.yaml 设 memory.provider: post-cortex）。
  • 启动 daemon：pcx start；用 hermes memory status 检查连通性。

本地选项仅在 $HERMES_HOME/post-cortex.json。PCX_TOKEN 走 Hermes secret scope，不会写入该 JSON。远程 daemon 需对齐 auth_token、PCX_TOKEN 与 daemon allowed_hosts。

最小示例：{"url": "http://127.0.0.1:3737", "workspaces": {"*": "hermes"}, "auto_recall": true, "mirror_memory_writes": true} — 完整键表见插件 README。

小结

  • 两条内置线：事实走 MemoryManager → Provider（落盘）；会话走 SessionDB + FTS5（检索）。
  • FTS5 + CJK：messages_fts_cjk 让 session_search 能跨会话检索，含中文。
  • 修过并发：写入路径只重读一次、在同一快照上做 drift 检测与解析，堵住被覆盖的竞态。
  • post-cortex（可选）：自托管 daemon 上的类型化实体图与语义召回；经 memory.provider 启用，可镜像主 Agent 的 memory 写入，按 workspace glob 共享图。
