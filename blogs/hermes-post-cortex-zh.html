post-cortex：Hermes 自托管语义长期记忆

post-cortex 插件与 daemon 如何为 Hermes 提供结构化、可共享的语义长期记忆——不替代内置 MEMORY.md，也不改写网关架构叙事。

DL
By Daniel Liu · October 18, 2026 · 12 min read

架构系列第 5 篇介绍可选社区 memory provider。内置 MEMORY.md 事实线与 SessionDB FTS5 见 第 4 篇。post-cortex 由 Hermes 插件 + 自托管 daemon 提供类型化记录实体图与本地语义检索（RocksDB 或 SurrealDB、本地 embedding），不替代前面章节的网关架构。

为什么另起一套？

Hermes 内置记忆刻意保持简单：事实写 markdown，会话用 SQLite FTS5。post-cortex 面向需要结构化知识（决策、已修复问题、代码变更、需求、定义）、每轮前语义召回、以及跨 profile / 客户端共享 workspace 且数据留在本地的场景。插件已进 hermes-agent plugin-catalog；代码在 hermes-plugin-post-cortex 与 post-cortex（Rust daemon）。

架构：插件、daemon、workspace

需要安装两件：catalog 插件 hermes-plugin-post-cortex，以及单独部署的 post-cortex daemon（pcx CLI）。插件是 Hermes 的 memory provider，不是个人 skill 包；唯一自带的 skill 是 post-cortex:memory（记录格式提示）。

每个 Hermes profile 通过 HTTP 连一个 daemon（默认 http://127.0.0.1:3737）。插件用 post-cortex.json 里的 glob 把 profile 名映射到 workspace，并打开每 profile 一条 session（默认 hermes:{profile}）。记录带类型化实体与关系；daemon 用本地模型做 embedding 与混合检索。除你配置的远程 URL 外，数据不离开自有环境。

轮次前召回

auto_recall 开启时，每轮开始前对 profile 对应 workspace 做语义检索。弱相关、空实体描述及 skip_patterns 命中的噪声会丢弃。高于 min_score（默认 0.62）的记录最多注入 max_items（默认 5）条，并按 item_chars 截断。daemon 慢或不可达时在 timeout_s 后跳过召回，轮次照常进行。

工具与 skill

  • post_cortex_search — 对记录（及可选 capture 消息）做语义搜索。
  • post_cortex_record — 写入类型化记录进图。
  • post_cortex_context — 指定组件的邻域与反向依赖。
  • skill_view("post-cortex:memory") — 记录格式与检索提示（post-cortex:memory skill）。

provider 负责召回、镜像与上述工具，除 post-cortex:memory 外不附带通用 skill 包。daemon 0.5+ 支持 cards（用户卡与项目卡写入 system prompt）、authorship（记录带 hermes:{profile}）、以及可选 capture 把完成的轮次写入消息流（仅主 Agent；cron 与子 Agent 不会自动写入）。

镜像内置 memory

mirror_memory_writes: true 时，主 Agent 通过 Hermes 内置 memory 工具保存的内容会同步为 post-cortex 记录。cron 与子 Agent 不会自动镜像。

多 profile 与 workspace

workspaces 用 profile 名 glob 映射到共享 workspace，先匹配者优先。例如 {"ops-*": "Ops", "dev-*": "MyProject", "*": "hermes"}。同一项目上的其他 post-cortex 客户端也可读同一 workspace。

安装与版本

需要 Hermes ≥ 0.22.2，daemon ≥ 0.4.0（cards、authorship、capture 需 0.5.0）。

Daemon。 用 cargo install post-cortex-daemon --features "embeddings,surrealdb-storage" 或 brew install julymetodiev/tap/post-cortex 安装 Rust CLI。执行 pcx start，默认地址 http://127.0.0.1:3737。配置写在 ~/.post-cortex/daemon.toml；非本机监听时设置 PC_AUTH_TOKEN（或文件内 auth_token），并在 allowed_hosts / PC_ALLOWED_HOSTS 中列出客户端主机名。

插件。hermes plugins install post-cortex，再 hermes memory setup 选 post-cortex，或在 profile config.yaml 设 memory.provider: post-cortex。新开 session 后，用 hermes memory status 确认 daemon 可达。

密钥与配置

连接。 URL：post-cortex.json 的 url，或环境变量 PCX_URL（默认本机）。Token：PCX_TOKEN 走 Hermes secret scope，不会写入 JSON。开启鉴权时，PCX_TOKEN 需与 daemon 的 auth_token / PC_AUTH_TOKEN 一致。

召回阈值、workspaces、capture 等插件选项也在 $HERMES_HOME/post-cortex.json。远程 daemon 需对齐 token 与 allowed_hosts，并建议在插件纯 HTTP 客户端前加私有网络或 TLS。

桌面端。Hermes Desktop 没有单独的 post-cortex 协议：在 GUI 中选 post-cortex 作为 memory provider 并填写 URL / token 即可。daemon 仍需先跑起来——常见做法是在本机先 pcx start 再聊天。

云端 / 共享主机。把 pcx 单独部署为服务（VM、容器或常开主机），各 profile 的 PCX_URL 指向该地址，并配置 token 与 allowed_hosts，否则客户端 Host 头会被拒绝。

最小示例：{"url": "http://127.0.0.1:3737", "workspaces": {"*": "hermes"}, "auto_recall": true, "mirror_memory_writes": true} — 完整键表见插件 README。

小结

  • 可选 provider：补充 MEMORY.md / FTS5，经 memory.provider 切换，不改网关主线。
  • 结构化 + 语义：自托管 daemon 上的实体图与本地 embedding；每轮注入少量高分上下文。
  • workspace 共享：glob 映射多 profile 与其他客户端。
  • 主 Agent 写入：镜像 memory 与可选 capture；子 Agent / cron 不走自动写路径。
